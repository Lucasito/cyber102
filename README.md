# Афиша культуры Башкортостана

Хакатон «Кибер102», задача №1 (заказчик — Министерство культуры РБ). Единая достоверная афиша культурных событий
республики: сайт с поиском и фильтрами, умный помощник (ИИ-агент), боты в MAX и Telegram, открытый REST API
и виджет для сторонних сайтов.

**Сайт:** https://afisha.193-47-33-213.sslip.io

**Уровень решения: 4 «Контур»** (по [ТЗ](docs/TZ.md), раздел 5). Что уже сделано и что в работе —
[docs/PLAN.md](docs/PLAN.md).

**Модель:** GigaChat-3-Ultra (Сбер, серверы в РФ), запасной провайдер — любой OpenAI-совместимый API; без модели
помощник работает по правилам и шаблону. **Стоимость диалога** на контрольном наборе — в среднем 0,87 ₽ (порог ТЗ —
3 ₽), p95 задержки — 2,5 с; расходы ограничены лимитами на диалог и на пользователя в сутки (админка → «ИИ»).
Подробно — [docs/DECISION.md](docs/DECISION.md) и [eval/report.md](eval/report.md).

> Сервис не является официальным сервисом Министерства культуры РБ. На сайте — только реальные события из
> подключённых источников (раздел админки «Источники»), прошедшие модерацию. Выдуманных событий нет нигде, в том
> числе в тестовых данных: локальный запуск и контрольный прогон используют снимок реальной афиши
> (`data/real-events.json`) — у каждого события исходный источник и ссылка на него.

## Запуск одной командой (чистая машина)

Нужен только Docker:

```bash
docker compose up --build        # ≈ 3–5 минут: сборка, миграции, реальные события (свежий снимок афиши или data/real-events.json)
```

Откройте http://localhost:3000. Админка — http://localhost:3000/admin, логин `admin`, пароль — в логе:
`docker compose logs app | grep bootstrap`. ИИ необязателен: без ключа помощник отвечает обычным поиском по правилам;
ключ GigaChat или OpenAI-совместимого API задаётся в админке → «ИИ-помощник».

## Быстрый старт (локально)

Нужны Node.js 22 и Docker.

```bash
cp .env.example .env          # DATABASE_URL уже указывает на локальную БД
npm install
npm run db:up                 # PostgreSQL 16 в Docker на 127.0.0.1:5435
npm run db:migrate
npm run seed:real             # реальные события из снимка data/real-events.json (-- --fresh — свежие из API афиши)
npx tsx scripts/admin-user.mts admin --role ADMIN   # первый администратор, печатает пароль
npm run dev                   # http://localhost:3000
```

Ключи ИИ, токены ботов и почта задаются в админке: `http://localhost:3000/admin`.
Проверка ИИ из консоли: `npm run ai:check`.

## Персональные данные

Храним минимум (ТЗ, раздел 10):

| Что | Срок |
|---|---|
| Пользователь бота — только идентификатор в мессенджере (имя не сохраняется) | пока пользуется ботом |
| Избранное сайта — до 100 ID событий в `localStorage` браузера, без аккаунта и новых cookie; на сервере список не сохраняется | до удаления из избранного или очистки данных браузера |
| Подписки на изменения события в боте — ID пользователя бота, ID события и снимок публичных полей; только после подтверждения | до отписки (`/watches`, `/unsubscribe`) либо 30 дней после окончания события |
| Последние реплики диалога с ботом (для уточнений, не больше «памяти диалога» из админки) | стираются через 30 дней без сообщений |
| Запросы к помощнику для аналитики и трассы ответов (текст, разбор, события, стоимость; пользователь — только хеш адреса или id в мессенджере, по нему не восстановить человека) | 180 дней |
| Заявки и учётные записи организаторов (организация, имя, почта, телефон по желанию) — с согласием в форме заявки | пока действует учётная запись; отклонённая заявка удаляется сразу |
| Напоминания о событиях | до отправки; `/unremind` удаляет сразу |
| Сессии и ссылки из писем админки | до истечения срока |
| Обращения (сообщение; имя и контакт — только если человек сам их оставил для ответа) | 365 дней |
| Местоположение для «рядом со мной» в чате и ботах — только после кнопки «📍» и разрешения устройства | не хранится: только для одного поиска, в диалог, трассу и логи не попадает (в трассе — пометка «рядом, радиус N км») |
| Подписки в боте — только город и категория, привязаны к идентификатору в мессенджере | до отписки (`/unsubscribe`), удаляются вместе с пользователем бота |
| Подписки через API — только город и категория, без данных о человеке | до отписки (`DELETE` с ключом) |

Очистка — фоновая задача `purgeOldData` (`lib/server/jobs.ts`), раз в час. Логи не содержат персональных данных.

Сервис неофициальный: не является сайтом Министерства культуры Республики Башкортостан; пометка — в подвале сайта,
в виджете, в приветствии ботов и в описании API.

## Ограничения

- Агент знает только то, что есть в базе: качество ответов равно качеству данных из источников.
- Понимает условия, которые выражаются фильтром (дата, город, жанр, цена, возраст, Пушкинская карта, доступная
  среда, название, площадка, «ближе к центру», «на башкирском», «не дольше N часов», «после 19:00» / «вечером»). Длительность известна не у всех
  событий (у кино — всегда): без неё событие показывается с пометкой «длительность не указана».
- Жанры — по справочнику категорий; поджанры (балет, опера, оперетта, мюзикл) — по словам в названии и описании
  события, другие поджанры ищутся как жанр. Часть источников не сообщает поджанр и язык показа (у Театра оперы
  и балета нет описаний — «Лебединое озеро» не отличить от «Травиаты»): такие запросы помощник отвечает подборкой
  площадки или жанра и честно говорит, что точного совпадения нет.
- Лимиты частоты запросов считаются в памяти одного процесса — достаточно для одного контейнера; при нескольких
  экземплярах нужен общий Redis.
- Метрики посчитаны на собственном наборе (96 кейсов) на снимке реальной афиши во временной базе; 10 внешних
  запросов готовит проверяющий.
- На башкирском — интерфейс сайта, помощник и виджет (`data-lang="ba"`); перевод требует проверки носителем
  языка. Боты и `/docs` — только на русском.

Подробно — в [docs/DECISION.md](docs/DECISION.md), раздел «Границы применимости».
