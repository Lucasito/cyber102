# Админка: руководство

## Вход

Адрес: https://afisha.193-47-33-213.sslip.io/admin (маленькая ссылка «Вход для администраторов» — внизу главной
страницы). Вход — по логину и паролю; сессия хранится в браузере 30 дней, «Выйти» — внизу меню.

**Защита от подбора пароля:** после 5 неверных паролей подряд вход для логина закрыт на 15 минут (блокировка
хранится в базе и переживает перезапуск); с одного адреса — не больше 20 неудачных попыток за 15 минут; каждый
неверный ответ приходит не раньше чем через секунду. Блокировку снимает администратор: «Сохранить» в карточке
пользователя или «Новый пароль».

**Забыли пароль?** Если настроена почта (раздел «Почта») и у пользователя указан адрес — ссылка «Забыли пароль?»
на странице входа присылает письмо со ссылкой на новый пароль (действует 1 час, одноразовая). Без почты пароль
сбрасывает администратор.

**Первый администратор или потеря доступа** — из консоли сервера (печатает новый пароль, снимает блокировку):

```bash
docker exec afisha-app npx tsx scripts/admin-user.mts admin --role ADMIN
```

## Роли

| Роль | Что доступно |
|---|---|
| Администратор | Все разделы: настройки, пользователи, данные, аналитика |
| Модератор | Обзор, события (правка, ручной ввод), модерация, импорт, источники, организаторы, обращения, журнал, свой профиль |
| Организатор | Кабинет организатора: свои события — добавить по одному, загрузить файлом, отозвать неопубликованное; свой профиль. Всё, что он присылает, проходит модерацию |

Все изменения в админке применяются сразу, без перезапуска.

## Разделы

Меню слева: «Работа» (обзор, события, модерация, импорт, источники, организаторы, обращения, журнал, аналитика, трассы, данные),
«Настройки» (сайт, ИИ, боты, карта, почта, тонкая настройка), «Доступ» (пользователи, мой профиль). У организатора — только
«Кабинет организатора» и профиль. Редко нужные поля свёрнуты в блоки со стрелкой; блок с
изменёнными значениями раскрыт сразу.

### Обзор

Актуальные, все, отменённые впереди и тестовые события; запросы к помощнику, ответы без ИИ, пользователи ботов;
«Требует внимания» — что стоит проверить, со ссылкой на нужный раздел.

### События

Все карточки с фильтрами: все, на сайте, черновики, спорные, отменённые, прошедшие; поиск по названию, площадке
и городу. «+ Добавить событие» — ручной ввод: ссылка на источник обязательна, город и площадка сверяются со
справочником, дубль (то же название, дата и площадка) не создаётся.

Карточка события: все поля, публикация, статус («Отменено» — убирается из выдачи, по прямой ссылке видно с
пометкой; смена даты — статус «Перенесено» и прежняя дата сохраняются), «Спорная», источники (ссылки, тип,
когда получены), исходные записи из файлов, **история изменений** (кто, когда, «было → стало»). Кнопки:
опубликовать / снять с публикации, одобрить / отклонить (для спорных), отменить, удалить.

### Модерация

Очередь спорных карточек (на сайте не видны): причина («нет категории», «цена не указана»), источники.
«Одобрить и опубликовать» — карточка появляется на сайте; «Отклонить» — остаётся черновиком; «Исправить» — в
карточку события.

### Импорт

Загрузка CSV или JSON (до 5 МБ, до 5000 строк). «Код источника» — одинаковый для повторных загрузок одного
источника (например, `minkult`); пусто — по имени файла. Сразу после загрузки — отчёт по строкам: добавлено,
обновлено, без изменений, отклонено и почему (отклонённые — первыми). История загрузок с отчётами.

Повторная загрузка того же файла ничего не меняет; одно событие из разных источников сводится в одну карточку.
Формат колонок — на странице импорта; образец — [`docs/samples/events-sample.csv`](samples/events-sample.csv).

### Источники

Откуда сборщик сам забирает события (модератор и администратор). Типы:

| Тип | Когда | ИИ | Публикация |
|---|---|---|---|
| Универсальный формат — JSON | Учреждение публикует ленту по [нашему формату](/docs/format) | нет | с «автопубликацией» — сразу, без неё — модерация |
| Универсальный формат — RSS | То же в RSS 2.0 с полями `afisha:` | нет | так же |
| Страница с разметкой schema.org | Страница афиши с JSON-LD Event (как у «Афиши Уфы») | нет | так же |
| RSS-лента + разбор ИИ | Обычная лента сайта: даты, площадка и цена — текстом в карточках | да | всегда модерация |
| Индивидуальный парсер | Сайт без ленты и разметки — разбор HTML пишет разработчик | нет | так же, как у универсального |

Карточка источника: **«Проверить без записи»** — что прочитано и как каждая запись пройдёт импорт (у «RSS + ИИ» —
до 3 новых записей, это расход токенов); **«Собрать сейчас»**; история запусков с отчётами; разобранные записи
ленты. Настройки: адрес, город по умолчанию, интервал сбора, сколько новых записей разбирать за раз (у «RSS + ИИ»
это предел расходов: одна запись — около 1–1,5 ₽), автопубликация, заметка. «Разобрать ленту заново» забывает
разобранные записи — следующий сбор отправит их ИИ снова.

Всё собранное проходит те же проверки, что импорт: только Башкортостан, дата в будущем, дубли, **ссылка на
источник отвечает** (не отвечает — в модерацию). Источник без автопубликации и разбор ИИ создают только черновики
и не меняют события, уже опубликованные в афише. Сбор по расписанию идёт в фоне: раз в 10 минут проверяется, кому
пора. Начальный список — пять проверенных RSS-лент из [DATA_SOURCES.md](DATA_SOURCES.md) — добавляет команда
`npm run sources:seed` (выключенными: включите каждый после проверки).

### Организаторы

Модератор приглашает учреждения и компании, которые сами добавляют события: организация, контактное лицо, логин,
почта. С настроенной почтой организатор получает ссылку и задаёт пароль сам, без неё пароль показывается один раз.
Список: сколько событий прислал, сколько ждут модерации, когда входил; «Отключить» (сразу выходит), «Ссылка для
пароля». Учреждению с сайтом лучше подключить ленту — раздел «Источники».

### Кабинет организатора

Организатор видит только свои события и их статус: на модерации, опубликовано, отклонено. **«Добавить событие»** —
форма с обязательными полями (название, начало, город, площадка, ссылка на страницу события); **«Загрузить файл»** —
CSV или JSON в универсальном формате, до 500 событий. Всё уходит в «Модерацию» с пометкой «от организатора …»;
события, которые уже есть в афише, организатор изменить не может. Неопубликованное можно отозвать. Опубликовал или
отклонил модератор — статус меняется в кабинете.

### Обращения

Заявки организаторов, уточнения по событиям и вопросы — с сайта (`/feedback`, ссылка «Сообщить об ошибке» на
странице события) и через API. Новые / обработанные; «Обработано» — с отметкой, кто обработал. О новом обращении
приходит письмо всем пользователям админки с указанной почтой. Событие из заявки добавляется вручную или импортом —
только с источником. Хранятся 365 дней.

Фильтр по пользователю.

### ИИ-помощник

- **Умный поиск включён** — выключите, если ИИ нужно остановить: сайт продолжит работать с обычными фильтрами,
  боты ответят «умный поиск временно недоступен».
- **Провайдер** — GigaChat или OpenAI-совместимый API. «Автоматически» — GigaChat, если задан ключ.
- **GigaChat:** ключ авторизации (developers.sber.ru → GigaChat API), тип доступа (физлицо — PERS,
  ИП/юрлицо — B2B или CORP), модель — список из API Сбера.
- **Остаток токенов** — по группам моделей. Подсвечена группа текущей модели. Бесплатный пакет: Lite 250 млн,
  Pro 40 млн, Max 25 млн, Ultra 50 млн токенов на 12 месяцев, без ежемесячного пополнения. Один запрос
  пользователя — примерно 1,5–3 тыс. токенов.
- **OpenAI-совместимый API:** адрес (например, `https://openrouter.ai/api/v1`), ключ, модель — из списка или
  своя.
- **Нагрузка и лимиты** (свёрнуто):
  - *Одновременных запросов к GigaChat* — бесплатный пакет обрабатывает один запрос за раз; остальные ждут
    в очереди. С платным пакетом можно увеличить.
  - *Запасной провайдер* — если основной не ответил после повторов, запрос уйдёт второму (если настроен).
  - Под настройками видно состояние очереди и пометка, если провайдер временно отключён после сбоев.
- **Указания помощнику** (свёрнуто) — пожелания к тону и содержанию объяснений.
- **Проверить ИИ** — тестовый запрос с временем ответа.

Секретные поля (ключи, токены) не показываются: пустое поле при сохранении оставляет прежнее значение,
галочка «Очистить» удаляет его.

### Боты

**MAX:** включение, токен, приветствие (ответ на запуск бота и `/start`). «Проверить бота» — имя бота из API MAX.

**Telegram:** включение, токен, «Подключение» — режим («Опрос» через зеркало API — основной; «Webhook» —
запасной) и адрес API Telegram (Cloudflare Worker, см. [BOTS.md](BOTS.md)), приветствие. «Проверить бота» —
доступность Telegram через указанный адрес.

### Карта

Три варианта:

- **OpenFreeMap** (по умолчанию) — векторная карта на данных OpenStreetMap: бесплатно, без ключа, без лимитов и без
  cookies, подписи по-русски. Не загрузилась за 10 с — сайт покажет OpenStreetMap.
- **OpenStreetMap** — простые растровые плитки, запасной вариант. Правила OSM не рассчитаны на большую нагрузку.
- **Яндекс Карты** — нужен ключ; бесплатный тариф — 100 запросов в сутки. Не загрузилась (неверный ключ, исчерпан
  лимит) — сайт покажет OpenFreeMap. Показывается кнопка «Открыть в Картах», логотип и условия Яндекса не
  перекрываются — так требуют условия бесплатного использования.

**Как получить ключ Яндекс Карт:**

1. Войдите в Яндекс ID и откройте [кабинет разработчика](https://developer.tech.yandex.ru/services/).
2. «Подключить API» → **«JavaScript API и HTTP Геокодер»** → заполните анкету: тип использования (бесплатный —
   для открытого бесплатного сайта), название и адрес сайта `https://afisha.193-47-33-213.sslip.io`.
3. После подтверждения в разделе сервиса появится ключ (строка вида `xxxxxxxx-xxxx-…`).
4. **Ограничьте ключ адресом сайта:** в настройках ключа → «Ограничение по HTTP Referer» → добавьте
   `afisha.193-47-33-213.sslip.io` (и `localhost` для проверки на компьютере разработчика). Ключ виден в браузере
   посетителей — без ограничения его могут использовать чужие сайты за ваш лимит.
5. Админка → «Карта» → «Яндекс Карты», вставьте ключ, «Сохранить». Новый ключ начинает работать в течение 15 минут.

Лимиты и условия бесплатного использования показаны в кабинете разработчика у ключа.

**Координаты площадок** находит сервер сам — через геокодер OpenStreetMap (Nominatim), а не через ключ Яндекса
(ключ, ограниченный по адресу сайта, с сервера не работает). Раз в 5 минут — по несколько площадок без координат:
по адресу, иначе по названию; в сёлах — центр населённого пункта. Сменили адрес площадки в карточке события —
координаты найдутся заново.

### Почта

Письма пользователям админки: восстановление пароля, приглашение, уведомление о смене пароля. Поля: SMTP-сервер,
порт, TLS (порт 465 — включено), логин (для Яндекса — полный адрес), пароль (пароль приложения), адрес и имя
отправителя.

Хостинг сервера закрыл исходящие почтовые порты (25, 465, 587), поэтому письма идут через **посредника** —
Cloudflare Worker из [`docs/mail-relay-worker.js`](mail-relay-worker.js) (установка — в начале файла): сервер
отправляет письмо воркеру по HTTPS, воркер подключается к SMTP. В админке — адрес воркера и общий секрет.
«Отправить тестовое письмо себе» — на адрес из «Моего профиля».

Пароль SMTP хранится только в базе (таблица `Setting`) и в админке не показывается.

### Тонкая настройка

**Населённые пункты РБ:** импорт принимает только события в Башкортостане. Населённого пункта нет во встроенном
справочнике (21 город и районные центры) — сервер проверяет регион через геокодер; вне РБ — строка пропускается.
Сюда можно вписать сёла РБ вручную, если геокодер их не знает.

Все рабочие числа без правки кода, применяются сразу. Пустое поле — значение по умолчанию (оно подписано под
полем); значение вне допустимых пределов тоже заменяется на стандартное. «Вернуть по умолчанию» сбрасывает всё.

| Группа | Что настраивается |
|---|---|
| ИИ | ожидание ответа модели и очереди, число повторов при перегрузке и пауза, пауза после сбоя, кэш одинаковых запросов, температура разбора и объяснения, длина объяснения, память диалога в ботах, сколько событий в ответе |
| Поиск и сайт | карточек на странице, карточек под ответом в чате, радиус «Рядом со мной», возраст для «с ребёнком» и «с подростком», длительность события без даты окончания, период аналитики |
| Боты и напоминания | событий в ответе бота; за сколько часов напоминать, запасной интервал, за сколько дней до закрытия выставки |
| Тексты помощника | уточняющий вопрос, кнопки к нему и кнопки после подборки |

Лимиты запросов к помощнику — в разделе «ИИ-помощник» → «Нагрузка».

**Стоимость** («ИИ-помощник» → «Стоимость»): цена 1000 токенов по тарифу провайдера (по умолчанию 0,65 ₽ — GigaChat Max в синхронном режиме с НДС; для Ultra отдельной цены в прайсе нет),
лимит на диалог (10 ₽) и на пользователя в сутки (30 ₽). Пользователь — адрес на сайте и в API, аккаунт в боте;
диалог — пользователь плюс первая реплика. Превышен лимит — помощник отвечает без ИИ (правила + шаблон), в трассе
режим «без ИИ (лимит)». 0 — без ограничения; цена 0 — расходы не считаются.

### Аналитика

Запросы к умному помощнику с сайта, через API и в ботах (таблица `QueryLog`):

- число запросов, сколько раз помощник уточнял, сколько ответов дано без ИИ (перегрузка), сколько напоминаний
  ждут отправки;
- график по дням и разбивка по источникам (сайт, API, MAX, Telegram);
- **популярные запросы** — что ищут чаще всего;
- **чего не хватает в афише** — запросы, по которым ничего не нашлось или пришлось показать похожее (другие
  даты, жанр, город). Подсказка министерству и площадкам, каких событий не хватает;
- **расходы на ИИ**, средняя стоимость диалога и задержка p95 — с порогами ТЗ (≤ 3 ₽ на диалог, ≤ 6 с).
  Прогоны контрольного набора в сводку не входят.

### Трассы

Каждый ответ помощника (ТЗ 7.4): запрос, источник, пользователь, режим (ИИ / частично без ИИ / без ИИ из-за
сбоя / без ИИ из-за лимита), время ответа, токены, стоимость. Фильтры — по режиму и источнику. В трассе:
шаги (разбор запроса моделью, сработавшие правила, итоговый фильтр, каждый поиск по базе с числом найденного,
ослабления условий, объяснение), вызовы модели (провайдер, токены, задержка, ошибки), события-основания со
ссылками на источник и остальные реплики того же диалога. Адрес трассы — `/admin/traces/{traceId}`, где
`traceId` — поле ответа `/api/ai/chat`.

### Пользователи

Список пользователей админки: имя, почта, роль, доступ (выключить — пользователь сразу выходит), время последнего
входа и временная блокировка после неудачных попыток. Действия: «Ссылка на почту» (письмо со ссылкой на новый
пароль), «Новый пароль» (сгенерировать и показать один раз), «Удалить». Себя нельзя удалить, отключить или
понизить; последнего активного администратора — тоже.

Новый пользователь: логин (латиница, цифры, `. _ -`), имя, роль, почта и пароль. С почтой и галочкой
«Пригласить» пользователь сам задаёт пароль по ссылке из письма (действует 24 часа). Без пароля — сгенерируется

### Мой профиль

Своя почта (для восстановления пароля) и смена пароля. О смене пароля приходит письмо.

### Данные

«Загрузить тестовые данные» — пересоздаёт 38 тестовых событий с датами от сегодняшнего дня.
«Удалить тестовые данные» — удаляет их. Реальные события эти кнопки не трогают.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Помощник отвечает «Нашёл N событий…» без живого объяснения | ИИ перегружен или недоступен — «Проверить ИИ», остаток токенов. Подборка при этом правильная |
| Помощник долго думает | Очередь к GigaChat (раздел «Нагрузка»). Можно настроить запасной провайдер |
| Бот молчит | «Проверить бота»; бот включён; для Telegram — адрес воркера и режим «Опрос» |
| Нет кнопки бота на сайте | Бот выключен; кнопки обновляются раз в 10 минут |
