# Достоверность событий и справочник площадок

## Подтверждённые адреса

В `/admin/venues` доступны все площадки, поиск по городу, названию и его вариантам, а также фильтр «Адрес уточняется».
При ручном сохранении можно включить «Защитить адрес, город и координаты». Источник не меняет защищённое
местоположение: отличающийся адрес или существенно отличающиеся координаты попадают в `/admin/moderation`.
Зал наследует защиту здания. Если адрес зала защищён отдельно, изменение здания его не перезаписывает.

При изменении адреса прежняя точка на карте сбрасывается. Если новый адрес не найден, можно задать координаты
вручную. Сохранение устаревшей формы отклоняется: сначала нужно обновить страницу. Изменение города пересчитывает
ключи событий и сохраняет прежнее название с прежним городом как вариант площадки.

Миграция `20261114140000_data_quality` защищает существующие адреса с точными координатами. Дата проверки человеком
переносится только из соответствующих записей журнала. Все прочие даты проверки остаются пустыми.

## Варианты названий и залы

В карточке площадки добавляются название и город, как они приходят из источника. Город варианта может отличаться
от реального: например, ошибочная «Уфа» у площадки в Салавате. Импорт по этому варианту использует правильную
площадку и её город. Поиск событий и расписание помощника также учитывают варианты названий.

Существующие дубли объединяются отдельной формой внизу справочника. Модератор выбирает оставшуюся площадку и
подтверждает, что это одно здание или один зал. События, их источники и напоминания переносятся; совпадающие
сеансы объединяются. Название удалённой записи становится вариантом оставшейся. По одному общему слову здания
автоматически не объединяются. Неоднозначные старые названия требуют решения модератора.

Зал можно привязать к зданию. При импорте названия вида «известное здание, Большой зал» зал создаётся внутри
этого здания и получает его местоположение. Вложенные здания и циклические привязки запрещены. Объединение
двух залов допускается только внутри одного здания. API `/api/v1/venues` дополнительно возвращает `buildingId`
и `aliases: [{ name, city }]`.

## Повторная проверка событий

Одинаковый GUID RSS больше не означает, что запись никогда не изменится. Хранятся хеш записи ленты, хеш
страницы с её JSON-LD и время проверки. Изменение ленты проверяется при следующем сборе. Неизменившиеся
будущие события перепроверяются через 24 часа, в том числе после исчезновения из короткой RSS-ленты.
Объём проверки ограничен `maxItems` источника. Старые проверки обрабатываются раньше недавно проверенных.

Для остальных источников за сбор дополнительно проверяются до пяти детальных страниц будущих событий,
если они не проверялись последние сутки. Общая страница афиши не считается уникальным идентификатором сеанса.
Хеш учитывает JSON-LD: изменение даты или статуса только в разметке тоже обнаруживается.

Проверка выполняется при сборе источника, а не отдельным суточным таймером. Если источник собирается реже суток,
повторная проверка тоже будет реже. Структурированная разметка используется без ИИ; изменившиеся страницы без неё
могут потребовать разбора ИИ. Если страницу нельзя загрузить или прочитать, событие не объявляется отменённым
автоматически. Время неудачной попытки сохраняется, а содержимое не отмечается обработанным; повторные попытки
выполняются при последующих сборах, не вытесняя остальные страницы из очереди.

Изменения уже заполненных полей опубликованных событий и существующих записей из источников с модерацией сохраняются в `DataChange`.
До решения модератора исходная карточка остаётся прежней. В `/admin/moderation` показаны источник, поля «Было»
и «Стало» и кнопки принятия/отклонения. При принятии переноса сохраняется прежняя дата и пересчитывается ключ
дедупликации. Неотправленные напоминания о переносе или отмене ставятся в ближайшую очередь отправки.

Одинаковое предложение, в том числе отклонённое, не создаётся повторно. Если модератор уже изменил затрагиваемые
поля, устаревшее предложение нельзя применить поверх его исправления. Его следует отклонить после сверки.

## Автоматическое дополнение пустых полей

При каждом успешном обходе любого типа источника сборщик дополнительно читает до 10 разных страниц
уже известных предстоящих событий с пропущенной ценой, возрастом или местоположением. Сначала — события
ближайших семи дней, внутри приоритета — страницы с самой старой проверкой. Повторная проверка страницы —
не чаще раза в 24 часа, включая неудачные попытки. Частота обхода самого источника остаётся прежней.
Одна загрузка используется всеми этапами текущего обхода; ИИ для дополнения не вызывается.

Только точное совпадение названия события в JSON-LD или единственном H1; разметка конкретного сеанса
должна совпадать и по времени. Страницы репертуара без даты позволяют дополнить уже известное событие,
но не создать расписание. Используются явные `0+/6+/12+/16+/18+`, рублёвые цены/диапазоны и сообщения
«Вход свободный». Рекомендации других событий, меню и подвал исключаются. Неоднозначные значения,
скидочное «бесплатно», иностранная валюта и рекомендуемый закрытый возрастной диапазон не заполняют поля.
Цены в JSON-LD учитывают все предложения, а не только первое; для автоматического дополнения требуется
явная рублёвая валюта. Отсутствующая верхняя граница цены остаётся неизвестной.

Пустые поля дополняются автоматически, с URL, выдержкой из источника, способом извлечения и значениями
«было → стало» в журнале (`action=enrich`). Уже заполненные значения сохраняются, противоречия направляются
в модерацию. Поля с ожидающим/отклонённым предложением не дополняются в обход решения; явно очищенные
человеком поля также не восстанавливаются. Отменённые и прошедшие события исключены. Автодополнение
не публикует черновики и не меняет расписание.

Местоположение берётся из JSON-LD только при совпадении площадки/её варианта и города. Новые площадки
при дополнении не создаются. Защита адреса действует и здесь; координаты проверяются по допустимому диапазону.
Смена площадки во время загрузки страницы отменяет дополнение этой карточки. Обычный геокодер продолжает
находить координаты по дополненному адресу в фоновой задаче.

Новые импортированные события дополняются в том же обходе, в пределах общего лимита 10 страниц. Нет
явных сведений или страница не загрузилась — поле остаётся пустым. Результат («страниц / полей / площадок /
ошибок») добавляется в отчёт источника. Проверки хранятся в `SourceItem`, GUID начинается с `enrich:v1:`;
они не считаются новыми элементами RSS. Новая миграция для дополнения не требуется.

Разметка: [Offer](https://schema.org/Offer), [AggregateOffer](https://schema.org/AggregateOffer),
[typicalAgeRange](https://schema.org/typicalAgeRange).

## Очередь качества афиши

`/admin/quality` («Качество афиши» в меню) доступна администратору и модератору. Показывает идущие сейчас
и будущие события; прошедшие и отменённые исключены. По умолчанию — опубликованные на ближайшие 30 дней.
Можно выбрать 7 дней, все предстоящие, черновики, поиск по событию/площадке/городу и отдельную проблему.
Сначала идут уже начавшиеся события, затем ближайшие по дате. Внутри одной даты выше карточки с большим
числом незаполненных групп полей. Выдача — по 30 карточек, с переходами к редактированию события и площадки.

Четыре группы: нет минимальной цены; нет возрастного ограничения; нет площадки/адреса/точных координат;
нет ссылки на источник или есть ошибка последней проверки сборщиком. Бесплатно (`0`) и `0+` — заполненные
значения. Счётчики считают события, одно событие может входить в несколько групп. Поиск и период применяются
ко всем счётчикам, выбранная группа — только к списку.

Ошибки детальных страниц берутся из `SourceItem`, ошибки сбора — из `Source.lastStatus`. Более свежая успешная
проверка `EventSource.fetchedAt` перекрывает старую ошибку. «Ошибка проверки» не означает, что ссылка точно
перестала работать: сбой мог возникнуть при чтении или разборе страницы. Страница не делает внешних запросов;
успех загрузки ленты тоже не доказывает доступность всех страниц. Данные не придумываются и не исправляются
автоматически. Для этого раздела дополнительная миграция не требуется.

## Проверка и установка

```bash
npm run db:generate
npm run db:deploy
npm run test:data-quality
npm run typecheck
npm run lint
npm run build
npm run test:data-quality:ui  # дополнительно: страницы админки и API на собранном приложении
```

Интеграционные проверки создают и удаляют отдельную временную базу `afisha_quality_test_*` на локальном PostgreSQL.
Пользователю БД нужно право `CREATEDB`. Запуск с удалённым `DATABASE_URL` запрещён. Источники для проверок
обслуживает локальный HTTP-сервер, ИИ и отправка сообщений не используются.
