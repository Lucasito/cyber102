# Источники данных: сверка с ТЗ и текущим импортом

Проверено 13 ноября 2026 года. Область: культурные события, проходящие **только в Республике Башкортостан**. Источники должны читаться без оплаты, регистрации и выданного API-ключа. Проверка выполнена по публичным страницам, исходному HTML/JSON-LD, RSS и коду проекта; массовый сбор и запись событий в БД не выполнялись.

## Вывод

Для первых двух сборщиков рекомендованы **СГТКО (`sgtko.ru`) и Башкирская филармония (`bashgf.ru`)**: оба являются сайтами учреждений, дают даты, названия, площадки и числовые цены в HTML. Возраст и длительность заполнены не везде, поэтому неполные карточки требуют модерации. Для дополнения данных об Уфе полезна **«Афиша Уфы» (`afisha-ufa.ru`)**: найдены JSON-LD Event с ценами, координатами, длительностью и окончанием. Достоверность агрегатора нужно сверять с учреждением.

Для расширения географии подходят **Сибайский театр** и **Госоркестр РБ**. Для выставок, экскурсий и встреч — **Национальный музей РБ** и **библиотеки Уфы**, с отдельной обработкой периодов и расписания посещения.

Ни один источник в этой проверке не подтвердил полноту всех полей для всех своих событий. HTTP 200 и заполненные поля сами по себе не доказывают актуальность цены, отсутствие отмены или корректность времени окончания.

## 1. Что требует ТЗ

Основание — [ТЗ](TZ.md), разделы 6.1, 6.2, 6.5, 8.1–8.3, 9.1–9.2 и 11.

| Требование | Что это означает для сбора |
|---|---|
| Схема 8.1 | Название, категория, начало, город, площадка, адрес, описание, цена/бесплатность, возраст, источник; окончание, длительность, координаты и язык — при наличии. Служебные поля рассчитывает сервис |
| Карточка 6.2 | Показывать дату и время, площадку с адресом, описание, цену либо бесплатность, возраст, источник и ссылку на билеты при наличии |
| Сбор 6.5 | Не менее двух внешних источников; допускаются RSS, API и страницы учреждений. Для демонстрации разрешены публичные источники |
| Проверка 6.5 | Проверить доступность источника, дату в будущем и отсутствие дубля; спорные карточки направлять на модерацию; сохранять время проверки и уверенность извлечения |
| Достоверность 6.1 | Хранить сырой материал отдельно от нормализованного; идемпотентный импорт, журнал изменений, статусы и отмены |
| Подключение 8.3 | Новый источник добавляется через конфигурацию, без ручного изменения кода. Полный охват республики не обязателен |
| Заполненность 9.1 | Не менее 95% карточек с обязательными полями; импорт 100 событий без ручной правки и дублей |
| Качество сбора 9.2 | Проверка на 50 вручную проверенных карточках: точность не ниже 90%, дубли не выше 5%; отменённые события не выдавать как актуальные |
| Планировщик 6.5 | Для обещаний о бюджете, окончании и переездах нужны подтверждённые цены, длительность/окончание, адреса и координаты |

ТЗ не задаёт универсальную таблицу обязательности каждого поля схемы 8.1: часть полей явно допускается «если известно». Пять полей, проверяемых импортом, нельзя считать полным набором требований к публичной карточке.

Для постоянной эксплуатации перечень источников согласуется с заказчиком (6.5 и Приложение В). Это не мешает настоящей проверке публичных страниц. Бесплатный просмотр не является открытой лицензией на тексты и изображения; у «Нура» и «Культурного мира Башкортостана» явно указано требование активной ссылки при копировании.

## 2. В каком формате данные нужны сейчас

Рабочий вход — **UTF-8 CSV или JSON**, а не HTML сайта. Сборщик преобразует HTML/JSON-LD/RSS в строки импорта. Реализация: [import.ts](../lib/server/import.ts), [normalize.ts](../lib/server/normalize.ts), [загрузка файла](../app/admin/events-actions.ts), [образец CSV](samples/events-sample.csv).

- JSON: массив объектов либо `{ "events": [...] }` / `{ "items": [...] }`.
- CSV: заголовок и строки; разделитель `;`, `,` либо табуляция.
- Ограничение загрузки в админке: 5 МБ; ограничение `importRows`: 5000 строк.
- Обязательный минимум текущего импортера: `title`, `date_start`, `city`, `venue`, `source_url`. Без них строка отклоняется.
- Без распознанной `category` либо без цены запись создаётся черновиком с причиной модерации.
- Отсутствие адреса, описания, возраста или длительности сейчас не мешает публикации на уровне импортера. Это не подтверждение соответствия полной карточки ТЗ.
- Даты передавать ISO 8601 с `+05:00`, например `2026-11-21T18:00:00+05:00`; рубли — числами, неизвестные значения — `null`.
- Один сеанс — одна запись. Два показа в 12:00 и 18:00 должны остаться двумя событиями.

| Поля для файла | Значение / откуда брать |
|---|---|
| `id` или `external_id` | Внешний идентификатор **сеанса**, не внутренний ID БД. Для переноса нужен устойчивый ID, который не меняется вместе с датой |
| `title`, `description` | Название и краткое описание из источника |
| `category`, `tags` | Категория справочника и метки; вид учреждения сам по себе не доказывает вид события |
| `date_start`, `date_end`, `duration_min` | Начало, подтверждённое окончание, числовая длительность; текст «2 ч 10 мин» преобразовать в 130 до импорта |
| `city`, `venue`, `address`, `lat`, `lon` | Фактическое место сеанса; адрес учреждения допустим только для показа именно в этом учреждении |
| `price_min`, `price_max`, `is_free` | Рубли; `0` — только при подтверждённой бесплатности. «От 400» означает минимум 400 и неизвестный максимум |
| `age_limit`, `language` | Возраст 0/6/12/16/18; язык — только при явном указании. Двуязычное название не доказывает язык спектакля |
| `source_url`, `org_link`, `ticket_url`, `image_url` | Источник, организатор, билеты, изображение; URL источника должен сохранять связь с конкретным сеансом |
| `status`, `pushkin` | Текущий импорт понимает «черновик», «отменено», «перенесено», «билеты проданы» и английские варианты; `pushkin` — явное подтверждение Пушкинской карты |

**Служебные поля не берутся с чужого сайта.** Внутренний ID, `normalized_title`, `dedup_key`, `source_hash`, `created_at`, `updated_at`, `verified_at`, `confidence` создаёт наш сервис. Тип `PAGE`/`RSS`/`API` и код источника передаются в параметрах `importRows`. Одноимённые дополнительные поля JSON не будут автоматически обработаны: неизвестные колонки игнорируются. Загрузка файла через админку получает тип `IMPORT`.

`publication` (`PUBLISHED`/`DRAFT`) и `status` (`SCHEDULED`/`RESCHEDULED`/`CANCELLED`/`SOLD_OUT`/`PAST`) в БД разделены. Входное `status: "черновик"` — поддержанный способ удержать импортируемую запись от публикации. Поле `publication` из произвольного JSON текущий маппер не читает.

## 3. Какие источники дают нужные поля

«Есть» означает наличие в проверенной странице/карточке, а не гарантию для всего сайта. «Не подтверждено» означает, что поле не найдено в проверенной выборке; оно может быть на другой странице или в билетном виджете. Публичный API без ключа для перечисленных учреждений не подтверждён; найденный JSON-LD — часть HTML.

| Источник | География | Формат | Подтверждённые полезные данные | Пробелы и решение |

## 4. Конкретные проверки и проблемы источников

1. **СГТКО:** [«Есть, товарищ начальник!»](https://sgtko.ru/afisha/event/spektakl-h-jb-sh-t-r-urynba-ary-m-st-r-est-tovarishh-nachalnik/) — 14.11.2026 18:00, 400–700 ₽, 16+, указание синхронного перевода. Ссылка на [сеанс Quick Tickets](https://quicktickets.ru/sterlitamak-gtko/s514?min=1) подтверждает возраст, площадку и адрес. Окончание `18:00`, равное началу, считать неизвестным.
2. **Филармония:** [«Освобождение звука»](https://bashgf.ru/afisha/event/jubilejnyj-koncert-azamata-hasanshina/) — 14.11.2026 18:00, 600–800 ₽, Малый зал, Уфа, Гоголя, 58. Название в URL устарело; брать заголовок страницы. Окончание `18:00` недостоверно; возраст в проверенной карточке не найден.
3. **Афиша Уфы:** [«Щелкунчик»](https://afisha-ufa.ru/events/teatr-opery-i-baleta/31978-shchelkunchik/) — 21.11.2026 18:00, JSON-LD `endDate` 20:10, `duration` PT130M, 1000–8000 ₽, координаты; возраст 6+ в HTML. [Театр](https://bashopera.ru/repertoire/ballet/289/) подтверждает 6+ и 2 ч 10 мин. Но в HTML агрегатора у Яндекс Афиши есть отметка «нет мест», тогда как найденная JSON-LD-разметка содержит `InStock`. Это конфликт доступности конкретного продавца, не доказательство отмены всего события.
4. **Молодёжный театр:** «Цирк на поляне» на [15 ноября](https://teatrnmt.ru/afisha/) указан длительностью 35 минут, на [странице постановки](https://teatrnmt.ru/new-spectacle/czirk-na-polyane/) — 40 минут; в другом сеансе расписания встречается 45 минут. Не выбирать произвольно длительность для обещания «закончится до ...».
5. **Сибай:** в [афише](https://sibaidramteatr.ru/afisha.php) «Живее, чем код. Айдар 2.0» имеет сеансы 23.11.2026 в 14.00, 15.00, 16.00 и 17.00 на площадке СКТО, Горького, 27. Адрес самого театра в подвале другой — З. Валиди, 26. Это пример, почему нельзя брать адрес из подвала для всех событий.
6. **Культурный мир:** RSS отвечает 200, `application/rss+xml`, содержит 20 элементов. Найдена дата `31 Dec 1899` у месячного плана Туймазинского театра. У других месячных планов стоит последний день месяца в 00:00. Ни `pubDate`, ни такая метадата не являются датой отдельного спектакля. [План музея](https://www.kulturarb.ru/ru/afisha/plan-meropriyatij-nacionalnogo-muzeya-respubliki-bashkortostan-na-noyabr-2026-g) содержит расписание изображением.

## 5. Что нужно учесть в текущем коде до массового импорта

Это результаты проверки, а не внесённые исправления. Бизнес-логика в рамках исследования не менялась.

| Несоответствие / риск | Где | Практическое последствие |
|---|---|---|
| `dedupKey` содержит день, но не время и не город | `lib/server/normalize.ts`, `dedupKey`; `import.ts`, поиск existing | Сеансы одного названия на одной площадке в 14:00 и 18:00 объединяются. Проверено вызовом функции: одинаковый ключ. Нужны точное начало и идентичность площадки с городом; репертуар и сеансы различать |
| Источник уникален по `(source, url)` | `prisma/schema.prisma`, `EventSource`; `import.ts`, привязка ссылки | Один URL постановки/общей афиши нельзя нормально связать со всеми сеансами. Нужна связь источника с сеансом по внешнему ID и поддержка нескольких записей для общего URL |
| `source_url` проверяется только как строка HTTP(S) | `lib/server/import.ts`, `normalizeRow` | Нет сетевой проверки статуса страницы, факта присутствия сеанса, отмены и переноса; `verifiedAt` не доказывает такую проверку |
| Новым строкам назначается `confidence = 1` или `0.7` по отсутствию цены/категории | `lib/server/import.ts`, создание Event | Это не оценка фактического извлечения. Передавать результаты проверок из сборщика; неполные/противоречивые данные — в очередь |
| Импортёр не проверяет принадлежность населённого пункта РБ | `normalizeCity`, `normalizeRow` | `normalizeCity("Казань", ...)` возвращает «Казань». Нужен справочник региона и проверка фактической площадки, включая сёла |
| «От 400 ₽» разбирается как минимум и максимум 400 | `lib/server/normalize.ts`, `parsePrice` | Ложная верхняя граница цены. Проверено вызовом функции. Сборщику передавать `price_min: 400`, `price_max: null`, не текстовую цену «от ...» |
| Год для даты без года угадывается по ближайшему будущему | `lib/server/normalize.ts`, `parseDate` | Проверено: «11 ноября 18:00» при now=13.11.2026 превращается в 11.11.2027. У старой афиши это создаст ложное будущее событие; год брать из подтверждённого контекста источника |
| Неизвестный возраст допускается фильтром возраста | `lib/server/events.ts`, `ageLimit: null` | Найденное для ребёнка событие не обязательно подходит по возрасту. Для строгого ответа нужны подтверждённый возраст или явная неопределённость |
| Не обнаружены сборщики и реестр конфигураций источников | `lib/server`, `jobs.ts`; см. также `docs/PLAN.md`, уровень 4 | CSV/JSON-импорт уже есть; автоматический сбор из двух источников и добавление источника конфигурацией пока не подтверждены. В фоновых задачах — статусы, напоминания и очистка |

Дополнительно: `duration_min` должен быть числом минут — текущий `parseInt` не переводит «2 часа» в 120. Для обновлений нужно различать «поле отсутствует» и «источник подтвердил отсутствие значения», иначе менее полный источник может затереть цену/длительность другого. Стабильный внешний ID важен для отличия переноса от нового сеанса; повторение хеша строки сейчас пропускает повторную обработку, поэтому повторную сетевую проверку актуальности следует выполнять отдельно.

## 6. Рекомендуемый порядок подключения

1. **Два сборщика PAGE:** СГТКО + филармония. Выгрузка карточек с датами и ценами; неизвестные возраст/длительность сохранять пустыми и учитывать при модерации. Эти сайты дают две независимые организации, но не покрывают все жанры/города.
2. **Дополнение Уфы:** JSON-LD/HTML «Афиши Уфы» + сверка с оперой/драмтеатром. Парсить только текущий Event, отделять от `ItemList` и соседних карточек. Конфликты доступности и цены не решать автоматически в пользу агрегатора.
3. **География:** Сибайский театр и Госоркестр РБ; получать фактические адреса выездных площадок. У Госоркестра на проверенной странице есть Октябрьский, Салават, Стерлитамак и Нефтекамск.
4. **Жанры:** музейные выставки, экскурсии и библиотечные встречи. Период выставки хранить отдельно от часов доступа; не обещать посещение в понедельник на основании одного диапазона дат. Отсутствие цены не считать бесплатностью.
5. **Расширение:** Башдрама, Молодёжный театр, «Нур», Русский драмтеатр Стерлитамака; дополнение ценами и конфликтами длительности. RSS регионального портала — обнаружение материалов, затем первоисточник/OCR/модерация.

Не выбран для первого этапа [API PRO.Культура.РФ](https://pro.culture.ru/documentation/proAPI.pdf): документация требует ключ авторизации. [Сайт Туймазинского театра](https://театр-туймазы.рф/) отдаёт оболочку с требованием JavaScript: публичный источник, но формат фактической выдачи событий без запуска JS пока не подтверждён. У [театра кукол](https://teatrkukol-ufa.ru/) при проверке временная версия с билетной витриной; готовый HTML списка событий не подтверждён. Их нельзя заявлять уже готовыми простыми HTML-источниками.

## 7. Что нужно проверить для приёмки

Список сайтов сам по себе не закрывает уровень 4. После реализации необходимо:

- обеспечить конфигурируемый сбор минимум из двух источников, хранение исходного HTML/JSON/RSS и привязку нормализованных полей к доказательствам;
- перед публикацией проверять ссылку, будущее начало сеанса, регион, обязательные данные и дубль; для уже идущих выставок явно согласовать правило допуска по периоду, а не подменять дату открытия;
- обрабатывать отмены и переносы повторной проверкой; исчезновение со страницы или HTTP-ошибка не равны отмене;
- проверить раздельные сеансы, перенос, один URL на несколько сеансов, конфликт цены/возраста/длительности и недоступность источника;
- прогнать импорт 100 событий и вручную проверить 50 карточек с расчётом порогов ТЗ; отдельно контролировать 95% заполненности и дубли публичной выдачи не выше 2% (это строже порога дублей сбора 5%);
- для планировщика использовать подтверждённую длительность, цену на нужное число посетителей и время перемещения, явно сообщать об отсутствующих данных.

В этой работе выполнена проверка доступности и структуры выбранных страниц, прочитан импорт/схема/ТЗ и воспроизведены перечисленные случаи чистых функций. Полнота всех карточек, точность на 50 карточках, работа массового импорта и метрики приёмки **не измерялись**.
