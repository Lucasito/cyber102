# REST API и виджет

Афиша открыта для сайтов и приложений: API без ключа, CORS разрешён для всех источников.
Базовый адрес: `https://afisha.193-47-33-213.sslip.io`. Машиночитаемая спецификация — `GET /api/v1/openapi`
(OpenAPI 3.1). Страница для людей — `/docs`.

## Поиск событий

`GET /api/v1/events`

| Параметр | Тип | Описание |
|---|---|---|
| `q` | string | Поиск по названию, описанию и площадке |
| `city` | string | Город: `Уфа`, `Стерлитамак`… |
| `category` | string | Жанр: `theatre`, `concert`, `exhibition`, `museum`, `kids`, `cinema`, `festival`, `lecture`, `excursion` |
| `dateFrom`, `dateTo` | date | `YYYY-MM-DD` (местное время UTC+5) или полная дата ISO. Без `dateFrom` — с текущего момента |
| `priceMax` | int | Минимальная цена билета не выше, ₽ |
| `free` | bool | Только бесплатные (`true`/`1`) |
| `age` | int | Возраст зрителя: события с ограничением не выше; события без возрастной пометки — в конце списка (возраст неизвестен — уточнить у организатора) |
| `status` | enum | `SCHEDULED`, `RESCHEDULED`, `CANCELLED`, `SOLD_OUT`, `PAST`. По умолчанию — все, кроме прошедших |
| `pushkin` | bool | Только события, которые можно оплатить Пушкинской картой |
| `access` | enum | Доступная среда: `wheelchair` — на коляске, `hearing` — для слабослышащих, `vision` — для слабовидящих |
| `near` | string | Рядом с точкой: `широта,долгота` (например `54.7348,55.9579`). В ответе у событий — `distanceKm` |
| `radius` | number | Радиус для `near`, км: 1–300, по умолчанию 15 |
| `sort` | enum | `date` — по дате (по умолчанию), `price_asc` — сначала бесплатные и дешёвые, `price_desc` — сначала дорогие, `new` — недавно добавленные, `distance` — ближе к точке `near`. Без цены — в конце |
| `limit` | int | 1–100, по умолчанию 20 |
| `offset` | int | Смещение для постраничной выдачи |

Период ищется по пересечению: выставка, идущая месяц, попадает в выдачу на любой день внутри срока.

```bash
curl "https://afisha.193-47-33-213.sslip.io/api/v1/events?city=Уфа&dateFrom=2026-11-14&dateTo=2026-11-15&age=6&priceMax=1000"
```

Ответ:

```json
{
  "items": [
    {
      "id": "cm…",
      "title": "Сказка о царе Салтане",
      "startsAt": "2026-11-14T06:00:00.000Z",
      "endsAt": "2026-11-14T08:30:00.000Z",
      "status": "SCHEDULED",
      "priceMin": 400, "priceMax": 600,
      "ageLimit": 0,
      "imageUrl": null, "ticketUrl": "…",
      "venue": { "name": "Театр кукол «Сказка»", "city": "Уфа", "address": "…" },
      "category": { "slug": "kids", "name": "Детям" },
      "sources": [{ "source": "…", "url": "…" }]
    }
  ],
  "total": 7, "limit": 20, "offset": 0
}
```

Цены — в рублях; `priceMin: 0` — бесплатно, `null` — цена неизвестна. Даты — UTC (ISO 8601).
Неверные параметры — `400` с описанием (см. «Ошибки»). По умолчанию выдаются только опубликованные актуальные события (черновики и спорные карточки до проверки не выдаются никогда): отменённые
(`CANCELLED`) и прошедшие (`PAST`) не попадают в выдачу. Их можно запросить явно — `status=CANCELLED`; карточка
отменённого события по прямой ссылке открывается с пометкой.

## Ошибки

Единый формат для всех методов — `{ code, message, details? }` с подходящим HTTP-кодом:

```json
{ "code": "bad_request", "message": "Неверные параметры запроса", "details": [{ "param": "age", "problem": "Too big: expected number to be <=18" }] }
```

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | Неверные параметры или тело запроса; в `details` — что именно |
| 404 | `not_found` | Событие не найдено |
| 429 | `rate_limited` | Превышен лимит; в `details.retryAfterSec` и заголовке `Retry-After` — через сколько секунд повторить |
| 502 | `ai_error` | Сбой модели, который не удалось обойти (обычно не возникает: см. резервный режим) |

## Кеширование и трассировка

- Каждый ответ содержит `X-Request-Id` (можно передать свой в запросе) — по нему запрос находится в логах сервера.
- Справочники и карточка события отдаются с `ETag` и `Cache-Control` (справочники — 300 с, карточка — 60 с, список —
  30 с). Повторный запрос с `If-None-Match` получает `304 Not Modified` без тела.

## Справочники

| Метод | Ответ |
|---|---|
| `GET /api/v1/cities` | `{ items: [{ name, venues, events }] }` — города, где есть площадки; `events` — актуальных событий |
| `GET /api/v1/venues?city=Уфа` | `{ items: [{ id, name, city, address, lat, lon, events }] }` |
| `GET /api/v1/categories` | `{ items: [{ code, name, events }] }` — `code` — значение фильтра `category` |

## Обращения

`POST /api/v1/feedback` — заявка организатора, уточнение по событию или вопрос:

```json
{ "kind": "correction", "eventId": "…", "message": "Концерт перенесён на 20 декабря, см. сайт филармонии", "contact": "необязательно" }
```

`kind`: `organizer` | `correction` | `question`; `message` — 10–3000 символов. Ответ `201 { id, status: "received" }`.
Не больше 5 обращений в час с адреса. Обращение попадает модератору (админка → «Обращения»), ему уходит письмо.
С сайта — форма https://afisha.193-47-33-213.sslip.io/feedback.

## Подписки

Без персональных данных: подписка — город и категория, доступ — по ключу из ответа.

```bash
curl -X POST .../api/v1/subscriptions -H "Content-Type: application/json" -d '{"city":"Уфа","category":"concert"}'
# 201 { "id": "…", "key": "…", "feedUrl": ".../api/v1/subscriptions/{id}?key=…", "unsubscribe": { "method": "DELETE", "url": "…" } }
```

- `GET /api/v1/subscriptions/{id}?key=…` — лента: актуальные события подписки, сначала недавно добавленные (до 50).
- `DELETE /api/v1/subscriptions/{id}?key=…` — отписка, запись удаляется (`204`).
- Ключ можно передавать заголовком `X-Subscription-Key`. Неверный ключ — `404`, как несуществующая подписка.

В ботах подписка оформляется кнопкой «🔔 Подписаться» ([BOTS.md](BOTS.md)).

## Универсальный формат ленты и её проверка

Учреждения публикуют события лентой — JSON или RSS 2.0 с полями `afisha:` (пространство имён `urn:afisha-rb:1`).
Описание полей, примеры и проверка в браузере — страница [/docs/format](/docs/format); образцы —
`/docs/format/sample.json` и `/docs/format/sample.xml`. Поля совпадают с импортом файлов в админке.

```bash
curl -X POST .../api/v1/format/check -H "Content-Type: application/json" -d '{"url":"https://example.org/afisha/feed.json"}'
# 200 { "format": "json", "hint": "…", "items": 12, "events": 12, "ok": 11, "withIssues": 2,
#       "rows": [{ "row": 1, "ok": true, "title": "…", "startsAt": "…", "city": "Уфа", "venue": "…", "issues": [] }, …] }
```

Вместо `url` можно передать текст ленты: `{ "content": "…" }`. Формат определяется сам: `json`, `rss` (с полями
`afisha:`), `rss_plain` (обычный RSS — подключается только с разбором ИИ), `jsonld` (страница со schema.org Event),
`unknown`. Ничего не сохраняется. Лента не загрузилась — `422 fetch_failed`. Лимит — как у умного поиска.

## Планировщик «Выходной день»

`GET /api/v1/plan` — 2–4 события на один день: по времени, без пересечений, с оценкой переездов и общей стоимостью.

```bash
curl ".../api/v1/plan?date=2026-11-15&city=Уфа&budget=2000&persons=2&maxTravelMin=20&count=3"
# 200 { "ok": true, "items": [{ "event": {…}, "start": "…", "end": "…", "travelMin": 14, "cost": 400 }, …],
#       "totalCost": 1400, "travelMin": 14, "unknownPrice": false, "note": null }
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `date` | ближайшая суббота | День, `YYYY-MM-DD` |
| `city` | Уфа | Город |
| `budget` | без ограничения | Бюджет на всех, ₽ |
| `persons` | 1 | Сколько человек; стоимость = минимальная цена × число людей |
| `age` | — | Возраст младшего участника: события с ограничением не старше |
| `from`, `to` | 10:00, 22:00 | Свободное окно, `HH:MM` |
| `maxTravelMin` | 40 | Предел одного переезда, мин |
| `count` | 3 | Сколько событий хочется (2–4) |
| `types` | все | Типы мероприятий: слаги категорий через запятую (`theatre,cinema`) или повторами `types=…&types=…` |
| `transport` | transit | `transit` — общественный транспорт, `car` — автомобиль, `walk` — пешком |
| `keep` | — | До 4 ID через запятую: события, которые должны остаться в плане |
| `exclude` | — | До 100 ID через запятую: исключить из подбора |

Переезд — по прямой: `transit` — 20 км/ч + 10 минут, `car` — 25 км/ч + 10 минут, `walk` — 5 км/ч.
Та же площадка или залы одного здания — 0. Без точных координат — условные 20 минут и `travelUnknown: true`.
Это оценка, без дорожной сети и расписания транспорта. Выставки и
музеи ставятся в свободное время с 10:00 до 18:00, посещение — 90 минут. Отменённые события и события без
билетов в план не попадают. При равном числе событий предпочитаются события по расписанию, затем меньше времени
в дороге, затем дешевле. Уместилось меньше, чем хотелось, — пояснение в `note`.

Несовместимые условия — тоже `200`, но `ok: false` и список `violations`: какое условие мешает и минимальная
правка (`поднять бюджет до 2400 ₽`, `сдвинуть время: 12:00–19:30`, `разрешить переезд до 35 мин`). Если одной
правки мало — пара правок. В `best` — лучшее, что удалось (одно событие).

В умном поиске то же самое — по запросу «составь план на воскресенье: три события, 2000 рублей на двоих, без
долгих переездов»: условия разбирают правила, ответ собирает код.

`durationEstimated: true` — длительность принята условно: 120 минут для события без времени окончания и
длительности, 90 минут для гибкого посещения. Стоимость не включает транспорт; `unknownPrice` означает,
что сумма неполная. `keep` проверяется заново при каждом запросе: отменённое или снятое с публикации событие
даёт `ok: false`, а не подменяется другим. При замене с `keep` требуется запрошенное число остановок.
Интерфейс, общая ссылка и календарь — [FAVORITES_AND_PLANS.md](FAVORITES_AND_PLANS.md).

## Наблюдаемость

- `GET /api/health` — `{ ok: true }`, если приложение отвечает и видит базу (для Docker и мониторинга).
- `GET /api/metrics` — запросы, ошибки 4xx/5xx и задержка (p50, p95) по маршрутам API с момента запуска.

## Событие

`GET /api/v1/events/{id}` — событие с площадкой, категорией и источниками; `404`, если нет.

`GET /api/v1/events/batch?ids=id1,id2` — актуальные публичные карточки по списку (до 100 ID),
ответ `{ items, missing }`. В `items` — формат карточек сайта (`CardEvent`) с адресом площадки;
порядок произвольный. В `missing` — удалённые, неопубликованные и неизвестные ID без раскрытия причины.
Отменённые и прошедшие опубликованные события возвращаются со статусом. Кеш — 30 секунд.
Метод ничего не записывает в профиль: список избранного остаётся в браузере.

## Умный поиск (ИИ-агент)

`POST /api/ai/chat`

```json
{ "messages": [
  { "role": "user", "content": "куда пойти в субботу с ребёнком до 1000 рублей" }
] }
```

Для продолжения диалога передайте всю историю (до 20 реплик, роли `user` / `assistant`) — агент учтёт
прежние условия («а в воскресенье?»).

«Рядом со мной», «около меня», «поблизости» без местоположения — ответ с `askLocation: true` (вопрос, без событий).
Спросите у человека разрешение на геопозицию и повторите тот же запрос (без реплики-вопроса) с
`"location": { "lat": 54.73, "lon": 55.96 }` — подборка в радиусе «Рядом со мной» с `distanceKm` у событий; при отказе —
`"location": "denied"`, поиск по всей афише. Координаты используются только в этом запросе и не сохраняются.

Ответ:

| Поле | Описание |
|---|---|
| `text` | Объяснение подборки или уточняющий вопрос |
| `events` | Найденные события (как в `/api/v1/events`) — только из базы |
| `suggestions` | Подсказки для кнопок («Бесплатно», «С ребёнком»…) |
| `clarify` | `true`, если это уточняющий вопрос |
| `filter` | Применённый фильтр |
| `relaxed` | `true` — точных совпадений не было, одно условие снято (об этом сказано в `text`) |
| `why` | Почему событие в подборке: `{ [id события]: ["✓ сб, 15 ноября", "✓ от 500 ₽ (≤ 1000 ₽)", "✗ другой город (Стерлитамак)", "? возраст не указан"] }` — по условиям запроса; ✓ выполнено, ✗ условие снято при ослаблении, ? неизвестно. Формирует код, не модель |
| `askLocation` | `true` — для «рядом со мной» нужно местоположение: повторите запрос с `location` (см. выше) |
| `degraded` | `true` — ИИ недоступен или исчерпан лимит стоимости, подборка собрана обычным поиском по правилам (резервный режим) |
| `traceId` | Идентификатор трассы ответа — по нему администратор найдёт разбор запроса в админке («Трассы») |

Ошибки (формат — см. «Ошибки»): `400 bad_request` — неверное тело; `429 rate_limited` — превышен
лимит (по умолчанию 600 запросов в минуту и 10 000 в сутки с одного адреса, настраивается в админке; заголовок `Retry-After` — через сколько секунд можно
повторить). Если ИИ выключен, не настроен или перегружен, ответ всё равно приходит (подборка по правилам, объяснение по шаблону), но может
задержаться до минуты — запросы стоят в очереди.

Необязательное поле `lang`: `"ba"` — помощник отвечает по-башкирски (`"ru"` — по умолчанию).

## Виджет

Код с нужными настройками удобнее всего собрать в **конструкторе** — https://afisha.193-47-33-213.sslip.io/docs/widget
(живой предпросмотр, копирование кода). Или вставьте в любое место страницы:

```html
<div data-afisha-widget data-city="Уфа" data-limit="6"></div>
<script src="https://afisha.193-47-33-213.sslip.io/widget.js" async></script>
```

| Атрибут | Описание |
|---|---|
| `data-city`, `data-category`, `data-q`, `data-age`, `data-price-max`, `data-free`, `data-pushkin`, `data-sort` | Фильтры, как в API |
| `data-period` | `today`, `tomorrow`, `weekend`, `week` (7 дней), `month` (30 дней) — считается в момент показа |
| `data-limit` | Сколько событий показать (по умолчанию 6) |
| `data-layout` | `grid` — плитки (по умолчанию), `list` — список |
| `data-title` | Заголовок над событиями |
| `data-accent` | Цвет акцентов без `#`, например `c2185b` |
| `data-link` | `0` — без ссылки «Вся афиша» внизу |
| `data-cols` | `1`–`4` — максимум колонок плиток; на узком экране меньше (по умолчанию — по ширине) |
| `data-img` | `0` — без картинок: компактные карточки, дата текстом |
| `data-theme` | `dark` — тёмные карточки для тёмного сайта (без `data-accent` — светлый зелёный акцент) |
| `data-bg` | Фон виджета: прозрачный по умолчанию (виден фон сайта), `white` или цвет без `#` |
| `data-radius` | Скругление карточек, px: `0`–`24` (по умолчанию 16) |
| `data-lang` | `ba` — подписи и карточки на башкирском (перевод — из админки, «Сайт» → локализация) |
| `data-ask` | `1` — строка «Спросить помощника» над событиями: вопрос открывается в чате на сайте афиши (новая вкладка, `/?ask=…`) и отправляется сразу; сам чат во фрейм не встраивается |
| `data-font` | `system` — системный шрифт, `serif` — с засечками (по умолчанию Inter) |
| `data-height` | `auto` (по умолчанию) — по содержимому, без прокрутки; число — фиксированная высота, px |

Несколько показов одного события (то же название и площадка) — одна карточка с диапазоном дат и «N показов»;
остальные даты — на странице события. Посмотреть виджет на странице «чужого» сайта со светлым, бежевым и тёмным
фоном — `/widget-demo` (ссылка «На примере сайта» в конструкторе передаёт текущие настройки).

Виджет работает во фрейме (`/widget?…`): стили и скрипты сайта не затрагиваются, сайт министерства менять
не нужно. Карточки открывают событие на сайте афиши в новой вкладке. Встраивание во фрейм разрешено только для
`/widget`, остальные страницы афиши во фрейм не встраиваются.
